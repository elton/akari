# anchor —— 测量人物在每个片段里的真实位置

生成一份 manifest，供播放器按**人物包围盒**对齐，而不是按画布对齐。

## 为什么需要它

素材的画布比例不一致，而且**即使画布一致，人物大小也不一致**。实测：

| 状态 | 画布 | 人物高 / 画布 |
| --- | --- | --- |
| `listening` | 1008×1080 | 0.747 |
| `greeting` | 806×1080 | **0.905** |
| `thinking` | 806×1080 | 0.786 |

`greeting` 与 `thinking` 画布完全相同，人物高度占比却差了 15% ——
因为它们的定妆图构图本来就不同（挥手那张人物更大更靠上）。

所以**统一画布比例解决不了问题**。按画布贴图，每次切到 `greeting` 她都会突然放大 15%，
观感是"人物在跳"。按人物包围盒对齐才是对的。

## 为什么取全部帧的并集

不能只测首帧。手势抬手、发丝飘动会让轮廓在片段中途向外扩，
只按首帧对齐会导致人物在动作最大时被裁掉。并集是唯一能保证任何一帧都装得下的框。

## 用法

```bash
swiftc -O -framework AVFoundation -framework CoreImage anchor.swift -o anchor
./anchor assets/akari/anchors.json assets/akari/*.mov
```

输出同时打印各片段相对最高者的缩放系数，便于人工核对。

## 播放器怎么用

加载时读 `anchors.json`，对每个片段计算变换：把 `box` 映射到屏幕上的目标矩形，
而不是把 `canvas` 映射过去。状态切换时人物的大小与位置因此保持连续。

阈值说明：alpha > 8/255 才算作人物，用于忽略抠像在边缘留下的半透明噪声。
逐帧按 2px 步长采样 —— 包围盒精确到 2px 足够，全分辨率逐像素扫描是浪费。
